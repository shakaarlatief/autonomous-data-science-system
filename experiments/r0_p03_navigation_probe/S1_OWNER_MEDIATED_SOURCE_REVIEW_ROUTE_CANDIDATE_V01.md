Necessary acceptance observations for *this exact fictional-only handoff*:

1. Reviewer's complete private output is serialized deterministically or byte-frozen as a structured source-status record and includes an exact manifest/version fingerprint and a complete/partial record accounting.

| Output | Intended reader | Acceptable data | Disallowed data |

| Restricted source-status and challenge ledger | Owner and independently approved restricted reviewer/challenger | Complete source-specific evidence, possible gold/design hazards, original citations, versioning, uncertainty and dissent | Public Git, exposed coordinator, fresh blinded task author |

| Future author-source packet | Independently admitted blind task author | Verified **original** permitted full files/excerpts and all material context, independently screened rendered metadata | Reviewer rationales, private status labels, old gold, comparator-specific advantage cues or silently rewritten answers |

An author-packet input is never formed by stripping one `private` key from a general reviewer JSON object. It must be **constructed independently from original exact source bytes** against an authorized manifest and then challenged as an assembled disclosure surface. A reviewer-private context qualifier cannot be turned into a made-up author-visible “neutral” sentence.
