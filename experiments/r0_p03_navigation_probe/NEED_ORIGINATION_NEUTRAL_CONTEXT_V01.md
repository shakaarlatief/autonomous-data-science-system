# Autonomous Data Science System: neutral project orientation

**Information horizon:** This description is grounded in a historical project-repository snapshot. It is not a statement that any architecture, frontend or operation is deployed or current today.

The Autonomous Data Science System (ADS) is an evolving environment for conducting data-science projects. It combines adaptable model-based reasoning with explicitly preserved project knowledge, methodological guidance, evidence, human decisions and suitable deterministic checks. The goal is to make complex work reliable, inspectable, repeatable and understandable without assuming that every design idea is implemented.

Two related areas of work exist. **Project development** is the engineering and governance of ADS itself: its design rationale, decisions, source-code changes, documentation, schemas, tests, validation records and historical evolution. **The ADS Product** is the application and workflow being built for use in data-science projects. Project-level engineering evidence and Product-level behavior are related but are not interchangeable.

The historical repository describes a V1 application-code foundation and a **frontend evaluation/prototype track**, including a Project Cockpit interface. Its described interaction areas include project overview, data exploration, analytical work, decision history, guidance, human approvals and activity. A prototype description does not by itself prove a production deployment or integrated backend behavior.

Repository knowledge comes in different forms: current-at-a-given-time state, scoped decisions and contracts, code and tests, bounded validation evidence, and historical records explaining changes. They may disagree because of revision, maturity, scope or incomplete execution evidence. An information request can legitimately require distinguishing *what was proposed*, *what was recorded as selected*, *what code or tests contain*, and *what was demonstrably run*.

This orientation does **not** include original source files, exact decisions, historical questions, outcomes, answer locations or the complete current state. Its purpose is to provide enough domain context for an independent contributor to formulate plausible information needs. Whether any proposed need is answerable from authenticated evidence is a **separate later determination**.
