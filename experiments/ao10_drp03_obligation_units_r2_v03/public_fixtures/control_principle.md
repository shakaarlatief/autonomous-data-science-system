# Integrated Project Interpretation Record

**Decision token:** ACCEPT

## Context

This record captures an accepted interpretive principle for the Project system. The principle concerns how semantic meaning and governing authority are read together when several durable carriers describe the same Project concern. It does not select a storage technology, create a migration task, require a new validator, or direct an implementation change.

## Accepted principle

Project meaning is interpreted from the combination of the authoritative carrier, its temporal scope, and its explicit relations. A convenient navigation route is not itself authority. A generated view is not made authoritative merely because it is easier to read. Historical evidence remains historical evidence even when later architecture uses different representation.

This interpretation applies equally when a carrier is concise or extensive. Physical location may help discovery, but physical location alone does not determine identity, authority, or semantic meaning. A future architecture may preserve, amend, replace, split, or merge current representational patterns through governed evolution.

## Consequence

The accepted effect of this decision is the interpretation itself. It does not request a new implementation artifact. It does not create a new migration wave. It does not require an additional runtime service. Existing accepted contracts continue under their own temporal authority until changed by a separate governing act.

## Boundary

This principle does not authorize production implementation, physical migration, provider selection, oracle retirement, or authority switch. Those remain governed by their own accepted decisions and evidence requirements.

## Current effect

The interpretive principle is effective upon acceptance. No follow-on realization act is identified by this record.
