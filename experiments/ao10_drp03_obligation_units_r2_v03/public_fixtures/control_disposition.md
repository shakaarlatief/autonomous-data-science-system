# Candidate Lifecycle Disposition Record

**Decision token:** ACCEPT

## Context

Two descriptive labels had been used for the same candidate review state. The duplication created unnecessary ambiguity in historical reading but did not change implementation behavior, authority, migration status, or assurance evidence.

## Disposition

The label REVIEW-CANDIDATE-B is superseded by REVIEW-CANDIDATE-A for the subject governed by this decision. REVIEW-CANDIDATE-B is retained only as historical terminology for records created before this decision. REVIEW-CANDIDATE-A is the current label from the effective point of this decision.

The disposition takes effect through this authority record itself. No file relocation, code modification, schema conversion, validator change, deployment action, data migration, branch change, or provider action is implied.

## Historical interpretation

Earlier records that use REVIEW-CANDIDATE-B remain valid evidence of the terminology that existed at their time. They are not rewritten. Later readers interpret the old label through this disposition when reconstructing the current terminology.

## Boundary

This disposition does not alter any underlying obligation, constraint, sequencing rule, implementation status, qualification result, or activation state. If later work decides that a technical representation should also change, that work requires a separate accepted decision.

## Current effect

The lifecycle terminology change is complete when this disposition is accepted. No follow-on realization act is identified by this record.
