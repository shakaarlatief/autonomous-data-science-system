# DRP-03 R2 V0.3 Key-Author Instructions

You are constructing one independent reference key. You are not a decision reviewer.

Do not inspect the other key author's output. Freeze your output before any cross-key comparison.

At least one key author must have no MC-0029/R1 exposure. If you have prior exposure, state it.

## BIRTH

Use the frozen proposal-item catalog, minimal decision token, and bounded acceptance evidence.

For each proposal item decide:

- whether it is accepted normative semantics;
- normative kind;
- materiality;
- whether it requires a realization unit;
- RESTATED if the item was already governing immediately before the event and is not materially changed;
- DECISION_TIME_DELTA when accepted meaning is determinable only from acceptance-time evidence unavailable in the reviewer packet.

RESTATED and DECISION_TIME_DELTA are neutral for blind reviewer precision/recall.

Do not use memory to invent a prior governing baseline. Mark RESTATED only when the bounded evidence supports it.

For grouping, do not create one canonical partition. Record only pairs that are clearly:

- MUST_JOIN under all four realization-boundary conditions; or
- MUST_SPLIT because at least one independent realization/evidence/qualification/failure boundary exists.

Leave all other pairs unconstrained.

## LEGACY

Label candidate-only accepted realization obligations. Hidden material-gap witnesses and already-realized false-gap controls require independent repository evidence in your private key. Record exact evidence paths/revisions or a deterministic absence-search specification plus frozen result.

Do not treat your belief about implementation status as evidence.

## STATE

Derive expected outputs independently from the public V0.7 state rules. Do not inspect another author's expected outputs.

## Materiality

Material means omission could change authority, admissibility, required realization, migration/cutover behavior, protection/hold semantics, an accepted architecture boundary, or an owner-approved sequence.

## Ambiguity

Record genuinely equivalent non-material interpretations as allowed ambiguity. Material disagreements are not ambiguity.

## Provenance

Record provider/model, interaction environment, prior MC-0029 exposure, packet digests, all tools/evidence used, and whether you authored any proposal/protocol under evaluation.
