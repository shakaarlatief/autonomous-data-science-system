# Long-form conversation is now a first-class Cockpit design requirement

The existing compact native composer remains useful, but it is not sufficient as the complete conversation experience.

ADS must support substantial project dialogue in which the user can:

```text
hold long multi-turn data-science conversations
see previous user/system messages
revisit earlier discussion
continue old conversations
search/navigate conversation history
discuss visible project work without losing context
```

The current design problem distinguishes:

```text
Composer
Conversational response
Conversation history
Conversation Workspace
```

Candidate presentation modes remain open:

```text
docked Conversation Lens
Conversation Focus Workspace
split analytical/conversation workbench
canvas-anchored conversation expansion
direct Conversation specialist view plus Cockpit entry
```

The accepted principle remains:

```text
conversation is integrated and substantial
    but
consequential project truth does not live only in prose history
```

Decisions, Questions, Findings, Proposals, Investigations, Runs, approvals and other consequential outcomes should continue to map into structured project state and may be linked bidirectionally from conversation.

The full transcript means user-visible conversation, not unrestricted hidden model reasoning traces.
