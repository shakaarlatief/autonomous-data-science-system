## The preferred Phase-C evidence mechanism has changed

Generated-image UI concepts are no longer part of the preferred Cockpit design workflow.

The current process is:

```text
real external references where useful
    +
small browser-rendered design experiments
    +
continuous human comparison
    ->
progressively integrated Cockpit prototype
    ->
production implementation only after evidence and specification
```

A generated screenshot is not treated as a prototype.

The isolated design-lab code is intentionally disposable and learning-oriented. It does not replace the promoted `/cockpit` implementation.

# Human disposition required before the next design slice

The grid/world experiment should be reviewed using dispositions such as:

```text
PREFER
REJECT
COMBINE
REFINE
UNRESOLVED
```

The review does not need to select exactly one whole variant. A hybrid may be more appropriate, for example:

```text
G1 major/minor hierarchy
+
G2 low visual noise
+
G4 scale-aware fading
```

Primary review questions:

```text
Which substrate is easiest to look at for a long session?
Which preserves spatial orientation best?
Which interferes least with work-unit text and relations?
Which feels most professional and distinctive for ADS?
Does the choice hold in both light and dark appearance?
At project scale, does the world become appropriately quieter?
Does G4 local activity communicate useful state or feel ornamental?
```

Do not begin the next work-unit-grammar slice until this disposition is recorded, unless the project owner explicitly asks to parallelize.

The compact native composer is useful but not sufficient as the complete conversation experience.

