## Prototype V0 experimental question

Prototype V0 asks whether operationalized semantic machinery materially improves reliability beyond a strong reasoner and excellent prompting.

```text
B0
Strong generic LLM workflow.

B1
Same model/tools + the same four methodological concepts supplied statically.
No typed state, dynamic activation, action gate, or dependency repair.

P0
Same model/tools + typed project state + structured reusable knowledge
+ activation/applicability + prospective safeguards
+ dependency-aware repair + minimal state-driven action selection.
```

B1 remains the critical control. If B1 matches P0's critical-integrity and repair behavior at materially lower complexity or cost, P0 should be simplified or rejected for this project scale.

## Implemented benchmark

The synthetic 24-month customer-month churn case is generated by:

`prototype_v0/src/ads_v0/casegen.py`

Core hidden mechanisms are:

```text
true row unit = customer-month
stale README says row = customer
later periods contain known and new customers
baseline preprocessing uses validation information
account_state_code is generated after the target outcome
stale README says that field is available at scoring time
Phase 2 notice authoritatively corrects the timing claim
final test is protected final evaluation
```

The generator writes separate Phase 1 visible material, a withheld Phase 2 notice, and evaluator-only truth/self-tests.

Default case properties remain approximately:

```text

0.6884 legitimate validation AUROC

```

## Centralized generation reliability

`ModelGenerationError` now carries provider-neutral retryability and diagnostic metadata.

The OpenAI SDK's own automatic retries are disabled for clients created by the adapter so retry behavior is not silently nested inside provider code.

The common treatment runner owns the retry policy for B0/B1 and future P0.

Current default:

```text
2 additional retries for a retryable generation
```

Non-retryable provider errors terminate immediately.

The trajectory records successful generations, failed attempts, provider/model metadata, response IDs where available, and observable token usage.

## Real calibration CLI

`prototype_v0/src/ads_v0/calibrate.py` can run B0 or B1 against an already generated case.

Example:

```text
python -m ads_v0.calibrate \
  --bundle generated/development \
  --condition B0 \
  --run-id dev-b0-01 \
  --output results/raw/dev-b0-01
```

B1 uses the same model/runtime configuration with `--condition B1`.

Generated run artifacts include:

```text
trace.jsonl
summary.json
deterministic_evaluation.json
milestones.json
conversation.json
```

Local API credentials must stay outside the repository. `.env` and `.env.*` are ignored.

## P0 remains intentionally unimplemented

The experimental protocol requires genuine B0/B1 viability evidence before P0 is built.

Planned P0 state remains:

```text
ARTIFACT
FACT
ASSUMPTION
QUESTION
EVIDENCE
CLAIM
DECISION
OBLIGATION
ACTION
```

with:

```text
DEPENDS_ON
SUPPORTS
CONTRADICTS
ANSWERS
GENERATED_BY
```

and only four initial structured knowledge components.

Implementing P0 before real baseline calibration would weaken the falsification design by allowing interfaces or budgets to be tuned around the treatment.
