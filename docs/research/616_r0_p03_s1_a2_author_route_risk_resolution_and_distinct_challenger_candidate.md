## 1. Specific new finding after owner's UI confirmation

The owner explicitly confirmed that the already tested author-view witness was a **Temporary Chat outside the ADS Project**, with **no connected apps enabled** (Validation 286). The separate witness's full 10,497-byte original report and exact source-free attachment fingerprint were reconciled in Research 615/Validation 285. These are valuable independent-owner and candidate-session evidence channels.

OpenAI's **current** Temporary Chat documentation distinguishes **Personalized** from **Unpersonalized** Temporary Chat:

- A personalized Temporary Chat **may use existing memory, custom instructions and plugins**, even though temporary chats do not create/update memory. Personalized may be the default depending on the current interface/settings.
- An **Unpersonalized** Temporary Chat is documented not to use existing memory, custom instructions or plugins for personalization. It is therefore a more appropriate prospective blind-author session configuration.
- Temporary mode and non-Project location alone do **not** prove Unpersonalized mode. The owner's prior confirmation did **not** specify that setting, so the past witness's personalization is **UNKNOWN**, not incorrectly marked disabled.
- Temporary Chat can retain safety-related context and provider-side operation cannot be perfectly observed from a model's own report. A zero-personalization design is a bounded product behavior, **not** a cryptographic statement about zero model pretraining or every hidden context.

Primary product sources, directly checked 2026-10-29:

- https://help.openai.com/en/articles/8914046-temporary-chat-in-chatgpt
- https://help.openai.com/en/articles/8590148-memory-in-chatgpt

Separately, OpenAI documents that **built-in web search** is available in ChatGPT; it is not categorically the same as an account-connected app (https://help.openai.com/en/articles/9237897-chatgpt-search). The reported test-only author-view interface labeled web `VISIBLE_UNTESTED`. Therefore, even with zero enabled personal apps, there remains a potentially material public route to the **already published R0-P03 design and old experimental context in GitHub**.

The public ADS repository is an ordinary published repository and contains source and past design material under exact pinned Git paths. A successful read from **this project's authorized GitHub connector** is not a live negative-access observation from the future blind-author's built-in web route. Conversely, a generic web cache miss in a different session or read prohibition in public-cwd Codexless is not an access-denied certificate for that route. **Classify possible web reachability as a material exposure hazard; actual future-author web use and end-to-end exclusion remain UNTESTED.**

## 3. Why next work is a genuinely distinct challenger intake

The S1 A2 source-free tests have now established valuable candidate mechanics: prior separate-session reviewer-style **mixed text/PNG** exact delivery/decoding, **binary outbound** artifact reconstruction, and **owner-only five-record CMS readback**. They do not automatically bind a **real reviewer identity**, appoint a separate adversarial challenger, qualify actual confidential source-specific custody or grant historical source release.

The project cannot treat this engineering coordinator, the old method-text critic, the prior **test-only future-author witness**, or the source reviewer itself as an independent challenger. Nor should it create a second prompt inside the same reviewer session and claim independent challenge.

The new source-free handoff `experiments/r0_p03_navigation_probe/S1_A2_CANDIDATE_CHALLENGER_ROLE_INTAKE_V01.md` is therefore **challenger-specific**:

- Owner opens a **new distinct** non-Project, preferably Unpersonalized Temporary Chat, with zero connected apps.
- The only attachment is the *one public brief*, not an actual source, methodology/answer key, reviewer report or protected material.
- The candidate reports actual context/tool exposures and *how* it could later challenge a reviewer, including visibility limits, material conflict detection, output custody/recovery and role disqualification.
- Its possible disposition is `CHALLENGER_INTAKE_REPORTED_ONLY` or `CHALLENGER_INTAKE_HOLD`, **never ADMITTED/PASS**.
- The owner independently decides whether the potential challenger is actually distinct from the eventual reviewer and what future sources/report versions it may receive. Two AI chats within one account/provider may satisfy practical process separation only under an explicit, evidenced independence model; they are not authenticated separately controlled persons.

This intake is **new evidence for A2-R06 actor separation**, not repetition of a fake CMS/protected-output experiment or test of the already completed A2-R07 public brief.
