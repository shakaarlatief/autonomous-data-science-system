## 2. Anti-anchoring and whole-system interpretation

Evidence is classified as:

    TARGET_ARCHITECTURE_EVIDENCE
    TRANSITION_EVIDENCE
    CURRENT_IMPLEMENTATION_DEBT
    ADOPTION_EVIDENCE

A current implementation failure does not falsify the target unless the probe isolates a target requirement that cannot be satisfied without the failed property. A current mechanism PASS does not grant preservation rights. The unit of judgment is the integrated professional Project system.

## 3. Result classes and no-tuning rule

Every scored DRP returns exactly one primary class:

    PASS
    AMEND
    CURRENT_DEBT_ONLY
    INCONCLUSIVE
    HARNESS_INVALID

A PASS may carry a descriptive subtype such as PASS_DETECTIVE_FIRST or PASS_MULTIPLE_VIABLE_ARMS, but there is no aggregate architecture score.

After protocol freeze:

    questions and thresholds cannot change because of observed outcomes
    fixture/harness repairs create a new version
    invalid attempts remain preserved
    a failed candidate is not silently replaced in the same confirmatory run

HARNESS_INVALID applies if source/fixture digests drift, hidden evaluator material leaks, blind exposure is violated, a scored harness changes after scoring begins, thresholds change after observation, evidence boundaries differ without preregistered reason, or the result depends on inaccessible conversation state rather than frozen evidence.

A material AMEND pauses downstream probes whose target it changes. A successor candidate and affected protocol version must freeze before those probes resume.

        vocabulary and no preferred semantic route

No arm receives preservation or novelty preference.

Primary scenario packet must freeze before B/C/D are implemented. Its author must not be a designer of B/C/D. Preferred method is a fresh independent collaborator given whole-system requirements and historical owner information needs but not arm definitions or expected winner. If that cannot be arranged without contamination, use a mechanically selected historical owner-query/event corpus under a separately frozen rule.

Primary packet:

    12 tasks
    3 cold-start/current orientation
    3 cross-plane discovery
    3 impact-analysis/architecture evolution
    3 exact-source/authority/recovery

Research 217's 9 scenarios are legacy regression only.

Before arm construction freeze a representative corpus and SHA-256(path)-ordered split:

    60 build carriers
    20 maintenance/held-out carriers

If fewer than 80 qualify, use all qualifying carriers with a 3:1 split. Freeze the responsibility mapping used by B/C before scoring.

Metrics include task outcome, authority correctness, default-route usefulness, bounded-depth recall, irrelevant-source burden, authoring/derivation effort, maintenance agreement, maintenance drift and authored-versus-derived metadata.

Hard failures include derived evidence routed as authority, loss of exact source/revision, physical parent treated as exclusive semantic parent, central member registry as unique truth, or inability to represent required multi-context meaning without duplicating authority.

An arm is viable only if:

    >= 10/12 primary tasks PASS
    >= 8/9 legacy scenarios PASS or preregistered N/A
    zero hard authority/safety failures
    maintenance agreement >= 0.80 F1 where assignment exists
    adding held-out carriers changes <= 10% of pre-existing carrier metadata
        solely due to corpus growth

Among viable arms, prefer the structurally simpler arm unless a more complex arm gains >=2 primary PASS results, >=0.10 maintenance-agreement improvement, or removes a material authority/navigation failure, while recurring authoring burden is <=25% higher.

If multiple arms remain non-dominated, return PASS_MULTIPLE_VIABLE_ARMS and carry the smallest unresolved choice to the owner. Research 217 may win.
