## 2. One build architecture

Research 179's central invariant is preserved exactly:

```text
FULL
    select every current view
    -> generate_views(current complete snapshot, all view IDs)

INCREMENTAL
    compare previous/current dependency state
    -> select affected view IDs
    -> generate_views(current complete snapshot, selected IDs)
```

Every selected incremental view therefore passes through the same G009 machinery as full rebuild:

```text
complete committed repository snapshot
-> production discovery/admission
-> complete canonical corpus
-> bind_view_inputs
-> qualified compute unit
-> deterministic serializer
-> manifest construction
-> public/private output validation
```

No changed-file delta is supplied to a view builder. No previous generated bytes are accepted as semantic inputs. Incremental refresh never patches persisted view state.

## 3. Deterministic impact analysis

`plan_view_refresh(...)` resolves both refs to complete immutable `COMMIT_SNAPSHOT` values.

For every current view it first checks the exact declared implementation closure across the two snapshots. A missing, added, removed, mode-changed or blob-changed implementation dependency selects the owning view as:

```text
IMPLEMENTATION_CLOSURE_CHANGED
```

For comparable view definitions, the previous and current states are each passed through the same isolated G009 admission/binding machinery without invoking compute. The resulting per-view impact envelope is:

```text
view_id
manifest_path
manifest_bytes
```

The manifest bytes already bind:

```text
view_id
view_path
view_schema_version
rebuildability_class
complete selected input paths + content digests + semantic IDs where present
generator ID/version
ordered implementation files + exact implementation digest
selector contract
compute identity
serializer identity
created/refreshed boundary
```

`manifest_path` is intentionally outside the accepted G009 manifest schema and is therefore carried by the G013 comparison envelope.

A changed envelope selects the view as:

```text
DEPENDENCY_BINDING_CHANGED
```

A new view is selected as `NEW_VIEW`. Removed view IDs are retained separately in the refresh plan.

## 4. Conservative fallback and global defects

Narrow impact selection is permitted only when the comparison can establish non-impact safely.

The accepted fallback behavior is:

```text
previous view definitions unavailable
    -> all current views selected
    -> BASELINE_SPECIFICATIONS_UNAVAILABLE

dependency/admission analysis unavailable or invalid
    -> all current views selected
    -> DEPENDENCY_ANALYSIS_UNAVAILABLE

known-private qualification probes supplied without prior validation receipt
    -> all current views revalidated
    -> PUBLIC_VALIDATION_CONTEXT_REQUIRED
```

Global repository defects remain fail-visible. Malformed declarations, duplicate canonical identity, private-path leakage and invalid capture authority cannot be hidden merely because the malformed carrier falls outside one narrow view selector.

The implementation deliberately prefers conservative over-selection over unsafe under-selection.

## 6. Independent adversarial review and repair

The first implementation was not accepted on its own test results.

Independent ChatGPT review found one real under-selection defect after the initial implementation:

```text
old manifest_path
    docs/project_knowledge/generated/manifests/current_state_core.json

new manifest_path
    docs/project_knowledge/generated/manifests/current_state_core_moved.json

initial G013 result
    affected_view_ids = ()
    full_fallback = false
    builds = ()
```

The root cause was precise: dependency analysis compared only `manifest_bytes`, while an accepted G009 manifest intentionally does not contain its own carrier path. A full build therefore returned a different complete `ViewBuildResult` even though the manifest bytes were unchanged.

The repair added `manifest_path` to the internal G013 impact envelope without altering the accepted G009 manifest schema. Permanent regression proves that a manifest-only relocation selects exactly the affected view and that its incremental result equals the full result.

A field-coverage regression now enumerates `ViewSpecification` fields so a future specification field cannot silently escape the impact contract. The post-repair audit found no other unbound current fields.

ChatGPT independently reran the relocation regression and the field-coverage regression after repair:

```text

```
