3. **Available restriction rather than hypothetical perfection:** Prefer model-native limited file tools, source-only APIs and fresh sessions where they genuinely bind the author-facing tool inventory. Otherwise record the specific live route as unverified, and assess whether hidden answers could actually be reached through it. 5. **Equivalent treatment and anti-tuning:** Prospectively fix and retain comparable source windows, metadata rules, tool inventory, prompts, budget, independent reference logic, scorer/version and run variance strategy. No owner content assistance after scores, cross-arm correction, reference edits, or parameter tuning based on hidden failure. Record failed/unknown separately. Do not log private keys, full hidden answers or private filesystem coordinates in public reports.

A non-enforcing prompt restriction **alone** can support an exploratory sensitivity analysis; it cannot become verified author blindness.
