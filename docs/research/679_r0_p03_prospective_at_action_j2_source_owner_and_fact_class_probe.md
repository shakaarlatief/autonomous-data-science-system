## 5. Design alternatives and discriminators

**A. Co-committed source-local RELATIONAL manifest.** Strong causal link and easy exact reproduction when the realizer is a repository source change. Weak if a different provider performs a non-Git action, if the author is not authenticated, or if a later model attempts to self-certify authority.

**B. Provider-native durable execution receipt translated through an ADS-owned typed evidence port.** More appropriate for external/ephemeral actions, especially when provider attestation, idempotency and independent status recovery are available. Not every provider exposes qualified proofs; adapters must not silently fake certainty or duplicate system predicate semantics.

**C. Exact OBSERVABLE records plus selective natural-owner RELATIONAL facts plus durable EPHEMERAL receipts.** The most faithful conceptual match to Research 512's typed distinction. A J3 evaluator must own the qualification rules, accepted dependency semantics and fail-visible UNKNOWN. No additional RELATIONAL declaration is needed merely for a Git-native observable fact.

**D. Centralized registry of inferred source-to-effect meaning.** Insufficient as authority and vulnerable to duplicated ownership. A disposable derived query/index over qualified natural-owner sources remains acceptable, but cannot invent governing relationships or event proofs.

These are design options, not a chosen physical target. The project may redesign files, metadata, branches, workflows, CI/CD, storage, providers and migration at any level. A successful co-committed source receipt does not entitle Git to be mandatory for every EPHEMERAL fact.
