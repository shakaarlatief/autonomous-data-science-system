## 4. Scientific and architectural interpretation

The **real positive result** is that original governing/source/code/test/history fragments can be linked into a checkable evidence graph under exact Git identity. The **real limitation** is the evidentiary ladder: seeing a code function does not prove acceptance, seeing a test source does not prove it passed, seeing a reported suite result does not prove historical CI and seeing a record labelled accepted does not independently establish a new operative owner act. The checked edges are documentary relations only and may never become J1/J2 accepted effects via the retrieval layer.

This experiment provides active **architecture-reconsideration observations**:

| Observed condition | Classification now | Possible architecture consequence if persistent |
| --- | --- | --- |
| Original record reports later logical selection while preserving older historical decision and incumbent authority | Source-scope/lineage modelling requirement, not a falsification | A model unable to preserve historical and current scopes separately would require CLARIFY/AMEND/REOPEN |
| Module/test/source relationship exists without independently qualified effect-to-realizer semantics | Evidence/ownership admission gap | If natural-owner J2 cannot represent real relationships without invention, reconsider substrate assumptions |
| Historical test results are only document-reported; direct current run is separately observed | Historical execution receipt gap | If execution provenance/CI cannot be bound to exact source, revise evidence ingestion and verification architecture |
| Proposal explicitly requires a decision | Negative authority-class guard | Any architecture granting it accepted target status is a correctness defect |
| Generated checkpoint is 331 numbers behind routing at original pin | Derived-view freshness challenge | If derived state silently overrides source currentness, revise currentness/index architecture |
| Manual source closure remains partial outside one chain | Corpus and task-answerability evidence gap | Reconsider source selection, ingest mechanisms, ownership of links, and eventually architectural representation if closure cannot be made robust |

These are **active triggers to investigate**, not automatic authority changes or preordained reasons to keep current physical representations. The original D-036 logical semantics and controls still require proper owner-governed change procedures, but every implementation layer and development practice can be reconsidered from first principles when evidence warrants it.
