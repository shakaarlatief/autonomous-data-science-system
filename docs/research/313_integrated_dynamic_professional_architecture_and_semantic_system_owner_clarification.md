## 1. Clarification

The project is not trying to preserve the strongest-looking version of the current architecture. It is trying to derive, qualify and evolve the strongest professional system that current evidence supports.

This applies without exception to the semantic layer.

Research 217, the W0-W5 semantic substrate, current identity/authority/relation machinery, current subject vocabulary, current navigation pattern and every later semantic refinement are evidence and qualified prior work. None receives target preservation rights merely because it was expensive to build, previously accepted for an earlier scope, or currently works.

The target semantic architecture may retain, clarify, amend, split, merge, add, delete, replace or wholly redesign:

    semantic-subject architecture
    ontology / vocabulary
    subject hierarchy or polyhierarchy
    assignable versus navigation-only concepts
    preferred routes
    membership rules
    source-owned versus derived membership
    identity model
    relation model
    authority model
    temporal / lifecycle semantics
    provenance semantics
    retrieval semantics
    activation semantics
    navigation projections
    semantic indexes
    semantic migration and evolution mechanisms

The governing criterion is whole-system quality under current requirements and evidence.

## 2. Research 217 status

Research 217 remains important empirical evidence.

Its demonstrated lessons include that a physical folder hierarchy was insufficient as the sole semantic navigation system, controlled vocabulary improved reproducibility over unconstrained interpretation, sparse multi-membership was useful, semantic subjects needed separation from structural and resolver facets, and preferred routes helped deterministic navigation.

Those findings must be challenged and accounted for.

They do not force the target to retain:

    the existing 18 assignable subjects
    the six navigation parents
    polyhierarchy
    preferred_subject
    explicit authored memberships
    source-owned membership
    one catalog shape
    one generated subject index
    or even a subject-based architecture at all

The correct future question is not "which of the 18 subjects survive?" It is "what semantic organization, discovery, retrieval, activation and reconstruction architecture should the professional ADS Project system have now?"

## 3. Semantic architecture is part of the professional system

Semantic architecture is not a sidecar documentation taxonomy.

It is one architectural dimension of the integrated professional ADS Project platform.

The Project system must coherently relate at least:

    durable Project knowledge
    semantic identity
    semantic organization
    typed relations
    authority
    provenance
    lifecycle and temporal status
    workstream/control state
    reconstruction
    retrieval and context selection
    activation and orchestration
    continuity and recovery
    architecture evolution
    assurance/admission
    governed execution/delivery
    preservation/promotion
    migration/cutover

These responsibilities remain separable for ownership and reasoning, but their interfaces must be designed together.

Local elegance is insufficient if one subsystem weakens the whole.

For example, the strongest semantic architecture should be evaluated partly by how well it supports human navigation, machine reconstruction, relevant-context selection, AO activation, authority closure, impact analysis, migration reasoning and future architecture evolution. This does not imply that one semantic mechanism must serve all those purposes. The architecture must derive the right boundaries rather than assume them.

## 4. Multidimensional information model

The accepted information architecture and semantic organization are different dimensions.

A future physical/information-role location such as:

    project/knowledge/governance/
    project/knowledge/evidence/
    project/knowledge/operations/
    project/knowledge/history/

answers primarily what role the information plays and which responsibility owns it.

Semantic architecture answers what the information means, what it concerns and how it relates to other semantic entities.

Authority answers whether and where it governs.

Identity answers what persistent semantic object it is.

Lifecycle answers its current status.

Provenance answers where it came from and to which revision/evidence it is bound.

These dimensions may interact but must not silently substitute for one another.

## 5. Integrated-system design principle

Repository architecture, workspace architecture, information architecture, representation architecture, semantic architecture, AO, WARRANT-F, engineering/assurance, Git/workflow, provider integration, delivery, recovery and migration are architectural dimensions or subsystems of one professional system.

They must therefore be allowed to inform and challenge one another.

A valid design process may discover, for example:

    semantic design exposes a better AO activation model
    AO exposes a missing semantic distinction
    assurance exposes missing consequence or subject binding
    representation exposes a poor definition/state boundary
    information architecture changes natural ownership
    migration evidence reopens a semantic assumption

Such feedback is expected architecture learning, not process failure.

## 6. Dynamic professional architecture method

"From scratch" means no existing solution has privileged target status.

It does not mean discard accumulated evidence.

The professional loop is:

    accumulated evidence
        +
    current accepted requirements
        +
    new discoveries
        ->
    derive strongest current architecture
        ->
    challenge it
        ->
    qualify it
        ->
    accept prospectively
        ->
    realize and operate it
        ->
    observe new evidence
        ->
    reopen only the affected architecture when warranted

Accepted architecture continues to govern prospectively until explicitly clarified, amended, superseded or reopened through the governed evolution path.

This preserves temporal authority while allowing unlimited design freedom.
