## 2. High-value diagnosis accepted for browser testing

Claude's strongest diagnosis is that W1-W4 appear broader than the mechanisms they actually cover.

### 2.1 Glyph channel is weakly explored

The first round uses bare letters:

```text
Q / I / V / M / E
```

Those are typographic labels rather than genuinely visual category marks. They require reading and memorizing a letter-category association.

A new round should therefore isolate category-mark strategy explicitly.

### 2.2 W3/W4 silhouette diversity is narrower than intended

The existing structural candidates largely move the same chamfer mechanism among corners. That is useful evidence, but it does not yet test genuinely different topologies.

A stronger topology family is warranted.

### 2.3 Material/surface language is untested

The first round keeps the same surface material across every category. Research 046 had already named surface material as a candidate channel, but no executable comparison tested it.

A clean W1-versus-material comparison is warranted.

### 2.4 Internal layout and connector-port grammar remain real ideas, but have dependencies

Claude proposed:

```text
Port Grammar
Internal Layout Grammar
```

Both remain genuine candidates, not rejections.

They are deferred from this immediate browser round because:

```text
Port Grammar
    overlaps the still-unresolved connector-semantics slice

Internal Layout Grammar
    interacts strongly with semantic zoom / information-density bands
    and can accidentally imply runtime state through live-looking micro-content
```

Deferral is scope discipline, not narrowing by candidate count.

### 2.5 Aspect/proportion is worth testing cautiously

Different category proportions may be structurally honest, but the concept directly pressures the existing scanning/alignment constraint.

Therefore the browser experiment should use deliberately small deltas rather than dramatic card-size changes.

## 4. Additional ChatGPT synthesis: Inner Instrument Architecture

Claude's design-space diagnosis explicitly notes that inner frame architecture is underexplored, but none of the eight concept families isolates that channel without also adding content-like internal semantics.

This round therefore adds one additional family:

```text
C9  Inner Instrument Architecture
```

Mechanism:

```text
outer frame remains stable
+
small category-specific structural linework is embedded inside the frame
```

Examples may include:

```text
open bracket
crosshair corner
paired validation rule
stacked construction lines
split readout frame
```

The internal marks are deliberately structural rather than data-bearing. They should not look like live metrics, progress, status, or runtime state.

This candidate is useful because it tests the underexplored `inner frame architecture` channel without waiting for the richer Internal Layout Grammar dependency.

Risk:

```text
if too expressive -> decorative instrumentation / noise
if too faint      -> no category-recognition value
```

## 5. Expanded browser experiment structure

The next browser page should not force all mechanisms into one mixed comparison. It should expose many candidates while preserving causal clarity through presentation batches.

Batching is organization only:

```text
batching != rejection
```

### Batch A: category-mark strategy

Hold W1-like frame, typography, category color, G4 world and H4 interaction constant.

```text
G0  Letter Control
G1  Instrument Glyph Family
G2  Compact Marker Rail
G3  Scientific Marker Family
```

Question:

```text
Does a genuine visual mark improve pre-attentive category recognition
and/or premium product character relative to bare letters?
```

### Batch B: structural grammar

```text
S0  Chamfer Control
S1  Structural Topology Family
S2  Aspect & Proportion Family
S3  Inner Instrument Architecture
```

Question:

```text

alignment, coherence, or professional restraint degrades?
```

### Batch C: material channel

```text
M0  Plain Surface Control

```

Question:

```text

without becoming visual noise or a rendering artifact?
```

## 7. External-reference interpretation

Claude highlighted three useful precedent families:

```text
P&ID / technical instrumentation symbols
    small coherent primitive vocabulary under high information density

UML / software architecture conventions
    structural type differences through border/frame treatment

scientific plotting markers
    familiar geometric visual vocabulary for data-science users
```

The browser experiment should transfer mechanisms, not copy a product identity.

The scientific-marker concept is especially cheap to test because it uses a familiar geometric vocabulary while avoiding a bespoke iconography dependency.

## 8. Evaluation questions

Human review should not be reduced to one winner question.

For every batch ask:

```text
Which simply looks best?
Which feels most premium and professional?
Which category distinctions are visible before reading titles?
Which feels easiest to learn rather than arbitrary?
Which remains one coherent ADS family?
Which becomes gimmicky, noisy, or diagram-like?
Which survives both H4 baseline and Reduced in-box light?
Does Project Scene composition change the judgment relative to Category strip?
```

Batch-specific questions:

```text
Glyph batch
    do pictograms/markers help enough to justify learning/design cost?

Structure batch
    does stronger topology help or damage scanning/alignment?

Material batch
    is texture perceivable and useful, or merely decorative noise?

Integrated batch
    do improved category marks still work when W4 already carries
    silhouette + signature cues?
```
