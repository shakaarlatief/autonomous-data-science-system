## 1. Why this comparison exists

The owner identified a legitimate untested possibility:

    the earlier rich semantic design may have failed because
    later semantic reconstruction was asked to establish authoritative truth;

    if the model instead drafts the rich semantics and the owner
    directly accepts/amends them against the governing source meaning,
    the authority/reproducibility failure may no longer be decisive.

This possibility was not tested by R2.

R2 remains valid evidence against:

    INFERENCE_AUTHORITATIVE_RICH

It is not automatically evidence against:

    RICH_ACCEPTED

## 3. Candidate B: RICH_ACCEPTED

RICH_ACCEPTED is a fair rescue of the earlier ObligationUnit family.

It does **not** reuse the failed rule:

    independent later semantic reconstruction -> authoritative truth

Instead:

    model drafts rich semantic structure
    + owner sees governing source meaning beside the proposal
    + owner ACCEPTS / AMENDS / REJECTS
    + only accepted structure becomes J1 authority.

Its functional semantic model is the earlier ObligationUnit family, not the R2 measurement scaffolding.

Core rich object:

    stable unit identity
    source/revision/section anchors
    accepted normative proposition(s)
    owner-accepted unit boundary/grouping
    responsible semantic owner
    realization boundary
    expected evidence path
    activation/effective boundary
    governed deferral where applicable
    realization/evidence/qualification/activation references
    derived realization state

Earlier global state vocabulary may be represented as:

    UNLINKED | LINKED | EVIDENCED | QUALIFIED | OPERATIONAL | DEFERRED

The following R2 comparison-only fields are **not** treated as required production fields merely because the experiment measured them:

    restated
    decision_time_delta
    ambiguity
    key-author comparison provenance
    agreement metrics

Normativity, kind and materiality are included in the comparison only to the extent that the rich design requires equivalent accepted classification to create/organize obligation units. They are not granted value by default.

## 6. Comparison dimensions

### D1 Authority legitimacy

Can the representation become authoritative without relying on later unaccepted model inference?

Expected after the owner's proposed amendment:

    THIN_ACCEPTED  yes
    RICH_ACCEPTED  yes

This dimension alone therefore cannot choose between them.

### D2 Competency-question sufficiency

For every one of the 37 admitted SP-1 competency questions:

    identify the authoritative inputs actually required;
    determine whether THIN_ACCEPTED can supply them;
    determine whether RICH_ACCEPTED can supply them;
    identify any RICH_ONLY contribution.

A RICH_ONLY contribution must be impossible or materially worse under the thin J1/J2/J3 allocation, not merely represented in a different place.

### D3 Judgment timing / natural ownership

For every rich core field, classify:

    J1_KNOWABLE
    J2_NATURAL_OWNER
    J3_DERIVED
    OPTIONAL_DIAGNOSTIC
    UNSUPPORTED

A field is structurally suspect as mandatory J1 authoring when its natural truth does not exist until J2/J3.

### D4 Canonicality

Ask whether the rich field represents:

    one stable governing fact

or:

    a view/summary of other facts

or:

    a many-to-many relationship that should not be forced into one birth-time partition.

This is especially important for:

    unit grouping
    global realization state

### D5 Control power

Compare whether each candidate can deterministically drive:

    ActionContract generation
    admission/refusal/review
    realization-gap visibility
    lifecycle/effective-boundary handling
    reconstruction
    exact lineage
    recovery/control routing

### D6 Authoring and maintenance burden

Do not invent minutes or money.

Record structural burden:

    mandatory accepted fields
    mandatory owner judgments
    later coverage declarations
    executable predicate definitions
    duplicate-authority risks
    synchronization/update obligations
    generated-view maintenance

### D7 Failure modes

Record whether each candidate creates new risks such as:

    duplicated authority
    stale summary state
    premature realization decisions
    forced canonical grouping
    opaque free-text slots
    excessive owner review surface
    loss of useful semantic distinctions

## 8. Outcome classes

### RICH_ACCEPTED_SUPERIOR

Use only if at least one current admitted competency question or required control outcome materially needs rich accepted structure and the added burden is justified.

### THIN_ACCEPTED_SUFFICIENT_RICH_OPTIONAL

Use if all current admitted machine questions/control outcomes are satisfied by THIN_ACCEPTED and rich-only fields add no demonstrated required capability, while some may remain useful as optional domain metadata, generated views or diagnostics.

### HYBRID_REQUIRED

Use if some specific rich fields provide demonstrated value, but the full rich unit model is unnecessary. The successor should admit those fields selectively into the appropriate natural owner/stage.

### RICH_ACCEPTED_REDESIGN_REQUIRED

Use if owner acceptance fixes authority legitimacy but mandatory rich structure still contains timing/canonicality/duplication defects that prevent using the earlier model substantially as-is.

### EVIDENCE_INSUFFICIENT

Use if the 37-CQ inventory and existing probe evidence cannot discriminate.

Multiple descriptive findings may coexist, but one routing class must be selected.
