## 5. Long-form conversation becomes a first-class Cockpit design requirement

The project owner added a material requirement that the current minimal composer alone does not satisfy.

ADS must support substantial multi-turn project discussion in which the user can:

```text
hold long data-science conversations
see previous user/system messages
revisit earlier discussion
continue old conversations
search or navigate conversation history
reason about visible project work with the system
```

The existing principle remains valid:

```text
chat integrated into the Cockpit
    !=
permanently dominant generic chat sidebar
```

The new requirement adds:

```text
compact native composer
    must coexist with
first-class Conversation Workspace / transcript experience
```

Potential product treatments such as docking, split workbench, focus transition, canvas-anchored expansion, or a direct specialist conversation view remain open and must be compared rather than selected by this checkpoint.

Consequential project outcomes must still map back into structured project state. A long transcript does not become the sole authoritative home of Decisions, Questions, Findings, Proposals, Investigations, Runs, or other durable project objects.
