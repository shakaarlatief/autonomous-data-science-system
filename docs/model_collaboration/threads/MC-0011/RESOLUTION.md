## 2. Main conceptual contributions

The dialogue established strong working conclusions, still subordinate to later empirical and external evidence:

```text
project-development knowledge architecture != ADS product architecture

reconstruction failure != situation-dispatch failure

situation dispatch should be externalized into project-controlled machinery
as far as practical rather than relying on model memory alone

consolidation/compression is a first-class cross-cutting scaling function

one stable entry means one stable router/bootstrap mechanism with task-shaped paths,
not one universal static orientation packet

requirements need evidentiary provenance rather than a flat appearance of equal proof

artifact-production pressure and active-knowledge-surface pressure are distinct

small high-stability bootstrap/constitutional core should contain protocol and pointers,
not changing project-state values or history-growing lists

reasoning control plane is a useful working concept for licensing project reasoning
based on task class, governing authority and uncertainty, but does not absorb Runtime
Bridge execution safety or collaborator write-ownership mechanics

distributed trigger/task declarations near governing sources plus a generated/rebuildable
dispatch view are conceptually safer than a second manually curated situation registry

routing/policy reasoning and ordinary work reasoning should be distinct by contract,
even if the same underlying model eventually performs both

active knowledge surface is a more useful scaling concept than total corpus size alone

architecture design remains reasoning-led; empirical probes and stress tests exist to
characterize/falsify mechanisms, not to replace architectural thought with a tournament
```

## 4. Active knowledge surface

The thread adopts as a working definition:

> **The active knowledge surface is the subset of durable project knowledge that must remain cheaply discoverable, reconstructable or triggerable for current and plausibly near-term work, distinct from deep provenance that remains durable but may stay latent until explicitly traversed.**

The working transition principle is asymmetric:

```text
promotion to active       explicit / deliberate
return to latent          default when governing/workstream relevance ends
```

Where possible, active status should later be derived from workstream/procedure/dependency state rather than maintained as a second manual per-artifact flag.
