## 4. Disposition of V0.2 concerns

Claude's concerns are useful design/qualification pressure, but none currently requires reopening the frozen requirements before source exposure.

### 4.1 KA-R07 governing/risk-bearing discovery boundary

Accepted as a **mechanism/qualification challenge**. A candidate must show how potentially governing/risk-bearing knowledge is surfaced without assuming it has already been found. This is exactly the kind of circularity a concrete authority-resolution mechanism must break.

The requirement's purpose remains valid; candidate synthesis must make the classification/resolution path concrete.

### 4.2 KA-R08 `receipt` terminology

Accepted as a wording caution, not a frozen-boundary failure. V0.2 defines a receipt behaviorally as evidence of traversal/decision state, not as one mandatory Markdown/log artifact. A live trace, re-derivable proof or another representation can satisfy the semantics if it makes the required state demonstrable.

Later design should avoid hardening `receipt` into a specific carrier unless evidence warrants it.

### 4.3 Evidence-weight visibility

Claude is correct that later users should be able to distinguish direct ADS evidence, owner constitutional choices and external transfer evidence without flattening them into one confidence class.

However, Research 130 already preserves that distinction more strongly than Message 001 implies:

```text
H   historical failure corpus
B*  blind ChatGPT baselines
D*  external deep-dive evidence
O/P/T owner/project/transition governance classes
```

and explicitly states:

```text
External evidence tags mean supporting transfer evidence,
not direct proof that ADS must copy a source domain's mechanism.
```

Research 130 Section 13 also separately identifies requirements primarily grounded in owner/project values rather than external empirical proof.

Claude's useful incremental point is therefore not that this distinction is absent, but that **the distinction may need to remain visible at the point of later requirement consumption and candidate justification rather than only in the reconciliation source**. Carry that as a provenance/view-design discriminator.

### 4.4 Dispatch reliability

Accepted as a useful **qualification metric**, not a new frozen requirement at this boundary. KA-R40/KA-R41 already require structural plus behavioral, multidimensional qualification. Repeated-trial dispatch reliability by task/situation class is a legitimate metric inside that qualification envelope where the candidate claims dispatch improvements.

Two ChatGPT runs do not establish a stable population success rate, so later work should not pretend they do.

### 4.5 Identity merge/split governance

Accepted as a real candidate-design problem. KA-R46 requires continuity where semantic identity is intended to persist; it does not prescribe how entity resolution, split/merge, duplicate detection or identity adjudication must work. Candidate families that introduce durable semantic objects must expose a credible governed answer or consciously limit where such identity is created.

This is a design challenge, not a reason to block owner-source exposure.

### 4.6 `C_failure`

Accepted. Candidate comparison should not count architecture maintenance costs while leaving failure cost as an empty symbolic term. Exact monetary estimation is unnecessary, but later synthesis/qualification should use at least consequence-aware qualitative severity/frequency reasoning grounded in the failure corpus and governed task classes.
