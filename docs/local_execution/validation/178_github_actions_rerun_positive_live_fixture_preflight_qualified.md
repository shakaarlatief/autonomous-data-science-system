## 5. Safety design for positive-live qualification

If separately authorized, the positive-live qualification should use exactly two mutation calls, one per distinct fixture, with no retry:

```text
Call 1
  github.rerun_failed_workflow_run_jobs
  repo_full_name = shakaarlatief/autonomous-data-science-system
  run_id = 33501596538

Call 2
  github.rerun_workflow_job
  repo_full_name = shakaarlatief/autonomous-data-science-system
  job_id = 99836356121
```

Before each mutation, perform a fresh read-only state check that the exact run/job remains `completed` + `failure` and the relevant attempt is unchanged. After each successful mutation, use read-only state to verify that GitHub accepted a rerun by observing a new run attempt / scheduled or completed rerun state.

If either mutation returns `mutationUncertain=true`, stop immediately and do not perform or replay the second mutation. No automatic retry is allowed.

Because both workflows are contents-read-only validators against historical immutable SHAs, the expected external effect is limited to GitHub Actions compute and run/job state. Repository contents, refs, issues, pull requests, releases and deployment state are not intended to change.
