ADS Cockpit Design Lab · Slice 02H · Conditional Runtime State

How should a work unit communicate a live execution episode without implying that every project-state box is executing?

The accepted work-unit category grammar, P7 Neutral Tag + Tone disposition treatment and current-process focus architecture remain conceptually separate. Runtime is now explicitly conditional: a work unit carries runtime state only when a meaningful current execution/work episode exists.

Held semantic separation Category ≠ disposition ≠ runtime ≠ priority ≠ focus membership Runtime may be absent.
Bounded design question

Give live execution state its own optional visual channel

Runtime answers “what is happening in the current execution/work episode?”. Deferred, Future and Completed work normally has no live runtime carrier. Current work may have no runtime or may be Queued, Running, Waiting, Waiting for Human or Failed.

Runtime is conditional No runtime ≠ Idle runtime Category remains dominant P7 disposition tag retained Motion is semantic only Readable without motion alone

Practical coexistence check

Does optional runtime remain legible when category and disposition are already present?

The scene deliberately mixes Current live work, a queued Next step, and Deferred/Future work with no runtime carrier. This tests whether absence remains clean while live execution remains legible.
